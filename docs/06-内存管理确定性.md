# 06 - 技术点4：内存管理确定性（按需分页 vs FSC 分区内存）

> 实时性代码对比系列。本系列：[02 形态](02-内核形态与启动流程.md) | [03 调度决策](03-调度决策机制.md) | [04 抢占与临界区](04-内核抢占与关中断窗口.md) | [05 中断路径](05-中断路径确定性.md) | **06 内存确定性** | [07 API路径与上下文切换](07-API路径与上下文切换开销.md) | [08 优先级继承](08-优先级继承.md) | [09 MICA核间通信](09-MICA混合部署与核间通信.md)

## 0. 本篇导读

**一句话结论**：Linux 的时延毛刺大本营在内存子系统——`malloc` 只建 VMA 不分配物理页，**首次写内存触发缺页**，缺页路径可走进页分配慢路径（唤醒 kswapd、直接回收、压缩、OOM），毫秒到秒级且上界不可静态确定；UniProton 是一块静态堆 + FSC（指数分级空闲链表 + 位图），申请 = 位图找级 + 摘链表头 + 分割，全程关中断、无 IO、无递归，最坏微秒级。**实时性代价**：Linux 换来了虚存超卖/隔离/换页/共享的全部弹性，UniProton 的内存上限就是物理堆大小、无硬件隔离、野指针可破坏任意内存。

**版本提醒**：6.6 已改为 folio API，`alloc_zeroed_user_highpage` 等旧函数名在 6.6 源码中已不存在（现为 `vma_alloc_zeroed_movable_folio`，include/linux/highmem.h:224）；6.6 的 `mm_init` 也已改名 `mm_core_init`。旧教材对照时注意。

## 1. 机制原理：分配被推迟 + 分配路径可睡眠 = 不确定

Linux 内存分配是**两层结构**：
- 第一层（malloc/brk/mmap）：只建立 `vm_area_struct`（虚拟区间描述符），**不碰物理内存**；
- 第二层（首次读写）：CPU 缺页异常 → 按页表项状态分派（匿名/文件/COW/换入）→ 真正分配物理页。物理页不足时进慢路径：唤醒 kswapd → 直接压缩 → 直接回收（扫描 LRU、迁页、写回）→ 重试 → OOM。

关键：**慢路径在缺页上下文里同步执行**。一条 `p[0] = 1` 语句的最坏内核代价可以串遍回收+压缩+OOM。

UniProton 没有这两层：`PRT_MemAlloc` 即时切块，返回的地址立即可写。没有缺页（无 MMU）、没有回收（没有 swap）、没有竞争者（没有后台线程）。

## 2. 架构设计对比

```
Linux：多层、按需、全局竞争                    UniProton：单层、预分配、无竞争
 mmap/brk → vm_area_struct（只记账）           链接期: rmem_start = 堆起点
    │                                          启动期: OsFscMemInit 整块挂为空闲块
    ▼ 首次读写（硬件缺页）                        31 条空闲链表 g_fscMemNodeList[]
 handle_pte_fault                                + 32 位位图 g_fscMemBitMap
    ├ PTE空 → do_anonymous_page               PRT_MemAlloc（关中断）
    │    └ 分配+清零+charge memcg+入LRU         ① 位图找 ≥size 的最低非空级
    ├ !present → do_swap_page（磁盘IO!）          ② 摘链表头（必要时同级扫描）
    └ 写只读 → do_wp_page（COW复制）              ③ 剩余够大则分割，插回低级
         │                                        PRT_MemFree（关中断）
         ▼ 物理页不足                               前后邻块 O(1) 合并 → 重新挂链
 __alloc_pages_slowpath
    ├ wake_all_kswapds（后台回收）
    ├ direct_compact（迁移压缩）
    ├ direct_reclaim（同步回收!）★ms级
    └ may_oom（杀进程）
```

## 3. 关键数据结构

**L1. `struct vm_area_struct`** — linux include/linux/mm_types.h:642：只有 `[vm_start, vm_end)` 区间与权限/ops，**不含物理页**——与页表项（PTE）分离正是"mmap 便宜、touch 昂贵"的结构性原因。

**U1. 块控制头 `struct TagFscMemCtrl`** — UniProton src/mem/include/prt_mem_external.h:28-47：

```c
struct TagFscMemCtrl {
    struct TagFscMemCtrl *next;    // 空闲时：双向链表指针
    uintptr_t size;                // 块大小
    uintptr_t prevSize;            // 前邻块空闲则记录其大小，否则=PREV_USED
    struct TagFscMemCtrl *prev;    // 空闲时：上一个控制块地址
};                                 // 占用时 next 写魔术字 0x5a5aa5a5
```

控制头内嵌在内存块首部；`prevSize` 让释放时 O(1) 找到前邻块合并。

**U2. 分级链表与位图** — src/mem/fsc/prt_fscmem.c:21-27：

```c
struct TagMemFuncLib g_memArithAPI;                    // 算法分发表(alloc/free函数指针)
struct TagFscMemCtrl g_fscMemNodeList[31];             // 31 条空闲链表头（2^N 级）
U32 g_fscMemBitMap = 1;                                // 位图：第 n 位=索引 n 的链表非空
```

索引 N 挂 [2^N, 2^(N+1)) 字节的空闲块（doc/zh/uniproton_functions.md:85-103 有官方图解）。

**U3. 任务栈静态化** — src/include/uapi/prt_task.h:1111-1130 `struct TskInitParam`：`stackSize`（创建时定死）+ `stackAddr`（传 0 则从 FSC 堆一次切出，prt_task_init.c:274-285；也可用户静态指定地址）。无动态增长，溢出靠栈顶魔术字检测（prt_task_init.c:257）。

## 4. 关键代码路径走读

### 4.1 Linux：一次 `p[0]=1` 的完整代价链

**① 缺页分派** — `handle_pte_fault()`（mm/memory.c:5796）四路分派：

```c
if (!vmf->pte)             return do_pte_missing(vmf);   // :5830 空→匿名/文件
if (!pte_present(...))     return do_swap_page(vmf);     // :5833 已换出→磁盘IO
...
if (vmf->flags & FAULT_FLAG_WRITE && !pte_write(entry))
                           return do_wp_page(vmf);       // :5846 写只读→COW
```

ARM64 入口 `do_mem_abort`（arch/arm64/mm/fault.c:1018）：按 ESR_ELx_EC 查 `mem_abort_table`（:961 起的 fault_info 表）分发，页错误走 `do_page_fault`（:644）→ `__do_page_fault`（:614），出错地址来自 FAR_EL1（`far` 参数），再进通用层。

**② 写匿名页 = 真实分配** — `do_anonymous_page()`（mm/memory.c:4799）：读缺页走全局零页不分配（:4819-4822）；**写缺页** `folio = alloc_anon_folio(vmf)`（:4848）进伙伴分配器 + `mem_cgroup_charge`（:4775）+ 限速等待 `folio_throttle_swaprate`（:4780）——三步都可能慢。

> ⚠ openEuler 差异：社区 6.6.159 在 do_anonymous_page 内直接调 `vma_alloc_zeroed_movable_folio`；openEuler-6.6 的基线已合入后期 stable 补丁，改为统一入口 `alloc_anon_folio(vmf)`（mm/memory.c:4717，mTHP 匿名缺页大页路径 `vma_alloc_folio`:4773，order-0 回退 `folio_prealloc`:4791，其内部再调 `vma_alloc_zeroed_movable_folio`:1061 + charge:1069 + throttle:1073）。"分配+charge+限速三步都可能慢"的结论不变。

**③ 慢路径全景** — `__alloc_pages_slowpath()`（mm/page_alloc.c:4367）：

```c
wake_all_kswapds(order, gfp_mask, ac);                    // :4426 唤醒后台回收
page = __alloc_pages_direct_compact(...);                 // :4451 同步压缩
page = __alloc_pages_direct_reclaim(...);                 // :4550 同步回收★ms级
if (should_reclaim_retry(...)) goto retry;                // :4573 重试
page = __alloc_pages_may_oom(...);                        // :4599 OOM
```

> ⚠ openEuler 差异：openEuler-6.6 的慢路径中有自有"可靠内存"补丁（`mem_reliable_fallback_zone`:4408、`mem_reliable_fallback_slowpath`:4428 等），并把 kswapd 唤醒提前；:4451 是 costly/高阶分配的前置压缩，retry 循环内还各有一次 `wake_all_kswapds`:4518 与 `__alloc_pages_direct_compact`:4556。行号以 openEuler-6.6 实测为准。

kswapd 常驻后台（mm/vmscan.c:7193，水线低于 low 被 `wakeup_kswapd`:7279 唤醒）——对实时任务它是**不可控的 CPU/内存带宽竞争者**。

**④ 对照：第一层为何便宜** — `SYSCALL_DEFINE1(brk)`（mm/mmap.c:223）与 `__mmap_region()`（mm/mmap.c:2826）只做记账+挂 VMA，无物理页分配（demand paging 的注释证据：mm/memory.c:5481-5483 "The VMA was not fully populated on mmap()"）。

> ⚠ openEuler 差异：社区 6.6.159 中 `mmap_region` 本体在 :2917；openEuler-6.6 已拆分为 `mmap_region()`:3092（入口）→ `__mmap_region_ext()`:3057（MDWE/arch 检查 + openEuler gmem 扩展）→ `__mmap_region()`:2826（记账主体）。"只建 VMA、不分配物理页"的结论不变。

### 4.2 UniProton：FSC 的常数时间操作

**① 分配** — `OsFscMemSearch()`（src/mem/fsc/prt_fscmem.c:29-71）：

```c
staIdx = OS_FSC_MEM_SZ2IDX(size);           // 31-OsGetLmb1(size)：size 最左1下标
*idx = staIdx + 1;
while (TRUE) {
    *idx = OsGetLmb1((g_fscMemBitMap << *idx) >> *idx);   // 位图找下一个非空级
    if (OS_FSC_MEM_LAST_IDX <= *idx) {                    // 只剩同级可搜
        currBlk = headBlk->next;
        while (currBlk != headBlk) {                      // 同级链线性扫描（有界）
            if (OS_FSC_MEM_SZGET(currBlk) >= size) return currBlk;
```

位图循环 ≤31 次；同级链扫描长度与碎块数相关——有界但非严格 O(1)（官方自评"申请释放效率较低"，doc/zh/uniproton_functions.md:79）。

**② 分割** — `OsFscMemAllocInner()`（:73-142）：摘块后剩余 ≥ 最小块则原位分割（:107-120），尾部写魔术字防越界（:129-131）。

**③ 释放合并** — `OsFscMemFree()`（:144-202）：

```c
if (nextBlk->next != OS_FSC_MEM_MAGIC_USED) {   // 后邻空闲：O(1) 合并
    OsFscMemDelete(nextBlk);  currBlk->size += nextBlk->size;
if (currBlk->prevSize != 0) {                   // 前邻空闲：O(1) 合并
    prevBlk = (void *)((uintptr_t)currBlk - currBlk->prevSize);
    prevBlk->size += currBlk->size;
OsFscMemInsert(currBlk, ...);                   // 重新分级挂链
```

**④ 外壳：全程关中断** — `PRT_MemAlloc/Free`（src/mem/prt_mem.c:18-56）：`PRT_HwiLock()` → `g_memArithAPI.alloc/free` → `PRT_HwiRestore()`。无优先级继承、无睡眠队列——失败立即返回错误码，**绝不等待内存**（对照 Linux 的 `GFP_KERNEL` 可以无限重试回收）。

**⑤ 堆的来源与无 MMU 证据**：
- 堆起点 = 配置数组 `g_memRegion00[]`（demos/hi3093/config/prt_config.h:89-90 `OS_MEM_FSC_PT_ADDR`），大小默认 0x80000（:96；libxml2 测试配置扩到 0x400000）
- 初始化：`OsFscMemInit(OS_MEM_FSC_PT_ADDR, OS_MEM_FSC_PT_SIZE)`（src/config/prt_config.c:28），整块清零后挂成单个空闲块并注册函数表（prt_fscmem.c:223-294）
- 无任务级地址空间：hi3093 链接地址即物理内存布局（hi3093.ld:8 IMU_SRAM 0x93000000 起）；MMU 仅作**静态段保护**（bsp/mmu.c 建 `g_mmu_page` 页表 + TCR 配置，protect/non-protect 段划分见 hi3093.ld:39-40），不做任务级映射切换——**无缺页、无 TLB miss 重填、无换页**三连成立。

## 5. 实现差异总结表

| 维度 | Linux 6.6 | UniProton |
|---|---|---|
| 申请时间上界 | 无静态上界（缺页→回收/压缩/OOM，ms~s 级） | 有界（位图 ≤31 级+同级链+指针操作，关中断内 μs 级） |
| 内存来源 | buddy 多级 ZONE+PCP+swap+page cache，全局竞争 | 链接脚本 rmem_start 起的一维静态堆 |
| 分配触发点 | 两层：syscall 建 VMA + 首次 touch 缺页 | 单层：PRT_MemAlloc 即时切块 |
| 毛刺来源清单 | 首写缺页清零、COW 复制、swap 换入 IO、慢路径回收/压缩、memcg/throttle、kswapd 抢 CPU、NUMA 迁移 | 同级链扫描（有界）、关中断窗口（可算）；无 IO 类 |
| 隔离/保护 | 页表硬件隔离、权限、memcg、OOM | 魔术字越界检测；无硬件隔离 |
| 灵活性 | 虚存>>物理、overcommit、换页、共享、COW、THP | 上限=物理堆；分配失败即报错；无共享/COW |
| 任务栈 | 动态、可扩张（VMA growsdown） | 创建时静态定死 |

## 6. 代码阅读指导

**推荐路线**：

1. `openEuler-6.6/arch/arm64/mm/fault.c:1018`（do_mem_abort 入口）→ `mm/memory.c:5796`（四分派）→ `:4036`（missing 分派）→ `:4799`（do_anonymous_page，重点 :4848 分配行）→ `:3748`（do_wp_page COW）
2. `openEuler-6.6/mm/page_alloc.c:4367`（慢路径全景，重点 :4426/:4451/:4550/:4599 四个停顿点）→ `mm/vmscan.c:7193`（kswapd）
3. `openEuler-6.6/mm/mmap.c:223`（brk）与 `:2826`（__mmap_region，入口 mmap_region():3092）——证明第一层只建 VMA
4. `UniProton/src/mem/prt_mem.c:18`（壳）→ `src/mem/include/prt_mem_external.h:39`（TagFscMemCtrl）→ `src/mem/fsc/prt_fscmem.c:223`（Init）→ `:29`（Search）→ `:73`（分割）→ `:144`（Free 合并）
5. `UniProton/doc/zh/uniproton_functions.md:83-113`（FSC 官方算法描述+图）与 `doc/design/mem.md`
6. `UniProton/src/core/kernel/task/amp/prt_task_init.c:127,274`（任务栈分配）+ `demos/hi3093/build/hi3093.ld:6-40` + `demos/hi3093/config/prt_config.h:87-96`（静态内存与段保护三件套）

**实验建议**：Linux 侧写程序 `p = malloc(1<<20); t0=now(); p[0]=1; t1=now();`，循环 1000 次记录 t1-t0 分布（用 clock_gettime）；再在内存压力下（stress-ng --vm）重复，观察长尾从微秒跳到毫秒——那就是慢路径。

**思考题**：

1. `p = malloc(1<<20); p[0]=1;` 两条语句各自的内核代价是什么？哪一条可能毫秒级？在哪一行代码分岔？（mmap.c:223 vs memory.c:4848→page_alloc.c:4550。）
2. FSC 位图为什么从"size 最左 1 的下标 +1"开始搜索（prt_fscmem.c:36）？不 +1 会怎样？同级链表最坏多长，如何用静态分析给出 PRT_MemAlloc 的 WCET？
3. UniProton 任务栈来自 FSC 堆（stackAddr=0 时）——"任务创建"的最坏时间由什么决定？对比 Linux fork+COW 首写的总代价，哪个对实时系统更可预测？
